# tetra — テトレーション (2 のべき乗タワー) を計算する迷路

ポート数を cp3-2 と同じくらい (約 400 個) にしたまま、 最短経路の長さを巨大数にした迷路。

## 考え方

- `nd-to-2d.py` で n レジスタの機械をゲーデル数化すると、 迷路の x 座標はゲーデル数 x = 2^a · 3^b · 5^c · 7^d になる。
- 2 レジスタの機械は x を 1 ずつ増やしたり減らしたりするので、 ステップ数は x と同じくらいの大きさになる。
- だから元の機械は、 規則が少なくて、 レジスタの値が大きくなるものであればよい。
- tetra の元の機械は、 4 レジスタで規則が 11 本である。 これで b を 2 のべき乗タワーにする。

## 元の機械 (`make-tetra.py`)

レジスタは (a, b, c, d) で、 素数 2, 3, 5, 7 が割り当てられる。 nd-to-2d の決まりにより、 (a, b, c, d) = (0, 1, 0, 0) から始まる。

| pc | 規則 | 意味 |
|---|---|---|
| 0 | a := A, d := M−1 | 準備 |
| 2 | a = 0 なら pc 5、 そうでなければ a−1 して pc 3 | 1 回の pass の外側のループ |
| 3 | b = 0 なら pc 4、 そうでなければ b−1, c+2 | b を 2 倍して c に移す |
| 4 | c = 0 なら pc 2、 そうでなければ c−1, b+1 | c を b に戻す |
| 5 | d = 0 なら HALT、 そうでなければ d−1 して pc 6 | pass の回数 |
| 6 | b = 0 なら b := 1 して pc 2、 そうでなければ b−1, a+1 | b を a に移して、 次の pass |

1 回の pass は b := 2^a (a := 0) を計算する。 だから M 回の pass のあと

- b = 2^2^…^2^A (2 が M 個)

になる。 ファイルは A = 2 に固定していて、 このとき b = 2↑↑(M+1) である。 M = 1, 2, 3, 4 で、 b は 4, 16, 65536, 2^65536 になる。

## ファイル

- `make-tetra.py` — 元の機械 (4 レジスタ Haskell) を作る。 `python3 make-tetra.py M [A] > tetra-M-4d.hs` (A を省くと 2)
- `Makefile` — `make` で tetra-2 〜 tetra-4 を作る。 `make tetra-1.maze` のように、 ほかの M も作れる。 nd-to-2d は `--fuse` 付きで呼ぶ。
- `tetra-M-4d.hs` — 元の機械 (M = 2, 3, 4)
- `tetra-M-2d.hs` — ゲーデル数化した 2 レジスタの機械
- `tetra-M.maze` — 迷路。 tetra-2〜4 は [visualizer](https://koteitan.github.io/repeated-maze/) の preset からも開ける。
- `count-steps.py` — 2 レジスタの機械を正確に動かして、 ステップ数を数える。 ループは一気に進めるので、 ゲーデル数が巨大でも数えられる。

## 規模とステップ数

S は 2 レジスタの機械の 「動くステップ」 (x か y が変わるステップ) の数、 L は迷路の最短経路の長さである。

| 迷路 | 最後の b | ポート | S | L |
|---|---|---|---|---|
| tetra-1 (`make tetra-1.maze`) | 4 | 332 | 10,927 | 21,863 (solver) |
| tetra-2 | 16 | 356 | 2,487,644,246,145 | 約 2S ≈ 5.0 × 10^12 |
| tetra-3 | 65536 | 380 | 8.137… × 10^45808 (45,809 桁) | 約 2S ≈ 1.6 × 10^45809 |
| tetra-4 | 2^65536 | 404 | 3^(2^65536) より大きい | 約 2S > 10^(10^19727) |
| (参考) cp3-2 | | 382 | 16,379 | 32,783 |

- tetra-1 の L は solver で解いた値である。
- tetra-2 と tetra-3 の S は `count-steps.py` で数えた正確な値である。 L はその 2 倍で見積もった。
- tetra-4 の S は数えられないが、 下からおさえられる。 HALT のときの状態は (a, b, c, d) = (0, 2^65536, 0, 0) なので、 ゲーデル数は x = 3^(2^65536) である。 nd-to-2d はゴールの前に x を 1 ずつ 0 まで減らすので、 その部分だけで 3^(2^65536) ステップかかる。 3^(2^65536) ≈ 10^(10^19727.98) である。

### L と S の関係

solver で解ける迷路では、 L は 2S より少しだけ大きかった。

| 迷路 | S | L | L − 2S |
|---|---|---|---|
| tetra-1 | 10,927 | 21,863 | 9 |
| cp3-2 | 16,379 | 32,783 | 25 |
| cp3-3 | 615,179 | 1,230,549 | 191 |

大きい迷路の L は、 この関係から 「約 2S」 と見積もっている。 L そのものは確かめていない。

## nd-to-2d の `--fuse`

ポート数を減らすために、 `nd-to-2d.py` に 2 つの旗を足した。 旗を付けなければ、 出力は前と同じである。

- `--fast-test`: ゼロのテスト (p が x を割らないか) を、 O(p²) 個ではなく 3p+1 個の pc で作る。
- `--fuse`: `--fast-test` も含む。 「r_j = 0 なら A、 そうでなければ r_j − 1 して B」 という 2 本の規則を、 1 回の割り算 (3p+3 個の pc) で作る。

tetra-3 のポート数は、 旗なしで 714、 `--fast-test` で 528、 `--fuse` で 380 である。 なお cp3-2 に `--fuse` を付けると、 382 ポートが 282 ポートになる。

## 確かめたこと

- 元の機械を直接動かすと、 tetra-3 は 196,754 ステップで b = 65536 になって止まる。
- `count-steps.py` の結果は、 1 ステップずつ動かした結果と一致した (tetra-1、 cp3-3 など)。 tetra-3 は 1 分弱で数え終わる。
- tetra-1 は solver で解けて、 ゴールに着く。
